# SPEC — 제품 명세

## 1. 제품 정의

### 1.1 한 문장

악보를 올리면 4파트로 나눠 파트별로 들려주는, 성가대원을 위한 연습 도구.

### 1.2 쓰는 사람

지휘자 한 명과 성가대원 20~40명. 대원 상당수가 40~70대이며 악보를 유창하게 읽지 못한다. 지휘자는 PC에서 악보를 올리고 인식 결과를 확인한다. 대원은 휴대폰으로 자기 파트를 듣는다.

**이 분업이 화면 설계를 결정한다.**

| 화면 | 주 사용자 | 기기 | 최적화 대상 |
|---|---|---|---|
| 악보 올리기 | 지휘자 | PC | 1920×1080 |
| 인식 확인 | 지휘자 | PC | 1920×1080 |
| 서재 | 대원 | 휴대폰 | 375~430 폭 |
| 연습 | 대원 | 휴대폰 | 375~430 폭 |

서재와 연습은 PC에서도 열리지만, 좁은 폭을 기준으로 설계하고 넓은 화면에서는 여백을 둔다. 올리기와 인식 확인은 휴대폰에서 열면 "PC에서 이용해 주세요" 안내를 띄운다. 좁은 화면에서 억지로 구겨 넣지 않는다.

### 1.3 1차의 전제

- 회원 개념이 없다. **모든 접속자가 같은 서재를 본다.**
- 진입 시 통행 암호를 한 번 묻는다. 암호는 `healing`.
- 서버는 운영자 소유이며 계속 유지된다.
- 곡별 연습 설정(마지막 파트, 마디, 빠르기)은 사용자마다 다르므로 **브라우저 localStorage에 저장한다.** 서버에 두지 않는다.

> **미래를 위한 표시** — 통행 암호 하나로는 링크 유출이나 검색 노출을 막지 못한다. 상용 전환 시점에 접근 통제를 다시 설계해야 한다. 관련 코드에 `// TODO(v2): 접근 통제 재설계` 주석을 남긴다.

## 2. 문구 규칙

**모든 사용자 대면 문구는 존대체로 쓴다.** 예외는 없다.

| 상황 | 규칙 | 예 |
|---|---|---|
| 안내 | ~합니다 / ~하세요 | "여기로 파일을 끌어다 놓으세요" |
| 버튼 | 명사형 또는 동사 | "파일 고르기", "한 옥타브 내리기" |
| 상태 | ~습니다 | "확인하실 곳이 3군데 있습니다" |
| 오류 | 무엇이 잘못됐고 어떻게 고치는지 | "오선 간격이 7픽셀입니다. 300DPI로 다시 스캔하시면 훨씬 정확해집니다" |
| 빈 화면 | 다음 행동을 권함 | "아직 올리신 악보가 없습니다. 첫 악보를 올려 보세요" |

**금지 사항**

- 사과하지 않는다. "죄송합니다" 대신 무엇이 일어났는지 말한다.
- 모호하게 쓰지 않는다. "오류가 발생했습니다" 금지.
- 내부 용어를 노출하지 않는다. "MusicXML 파싱 실패" 대신 "악보를 읽지 못했습니다".
- 한 낱말은 한 뜻으로만 쓴다. "파트"는 성부만 가리킨다. 곡의 부분은 "구간".

**용어 사전**

| 쓸 말 | 쓰지 않을 말 |
|---|---|
| 파트 | 성부(내부 코드에서만), 보이스 |
| 마디 | 소절, measure |
| 빠르기 | 템포, BPM(숫자 옆 단위로만) |
| 악보 따라가기 | 자동 스크롤 |
| 통행 암호 | 비밀번호, 패스키 |
| 인식 | 파싱, OMR |

## 3. 사용자 흐름

### 3.1 진입

```
접속 → 통행 암호 화면 → (healing 입력) → 서재
                       ↘ (틀림) → "암호가 맞지 않습니다" → 재입력
```

- 암호가 맞으면 서명된 세션 쿠키를 발급한다. 유효기간 30일.
- 쿠키가 있으면 암호 화면을 건너뛴다.
- 암호 화면에는 서비스 설명을 한 줄만 둔다. "성가대 파트 연습 도구입니다."

### 3.2 악보 올리기 (지휘자, PC)

```
서재 → [새 악보 올리기] → 파일 선택/끌어놓기
   → 형식 판별
        ├─ 벡터 PDF → 즉시 인식(1초 내) → 인식 확인 화면
        └─ 스캔 이미지 → 품질 진단 화면
                          ├─ 양호 → 인식 작업 등록 → 진행 표시 → 인식 확인 화면
                          └─ 불량 → 경고 + [다시 스캔하는 방법] / [이대로 진행하기]
```

### 3.3 인식 확인 (지휘자, PC)

```
인식 확인 화면
   ├─ 경고 없음 → [확인했습니다] → 서재
   └─ 경고 있음 → 항목별 교정 → [확인했습니다] → 서재
```

교정은 즉시 반영되고 서버에 저장된다. 되돌리기를 지원한다.

### 3.4 연습 (대원, 휴대폰)

```
서재 → 곡 선택 → 연습 화면
   → 파트 고르기 → 재생
   → (악보가 따라 내려감)
```

곡을 다시 열면 마지막 파트·마디·빠르기를 복원한다.

## 4. 화면 명세

### 4.1 통행 암호

| 요소 | 내용 |
|---|---|
| 제목 | 힐링콰이어 |
| 부제 | 성가대 파트 연습 도구입니다 |
| 입력 | 통행 암호 (type=password, 자동완성 off) |
| 버튼 | 들어가기 |
| 오류 | "암호가 맞지 않습니다" (입력란 아래, 붉은 글씨) |

세 번 틀리면 10초 대기를 건다. 무차별 시도 방지의 최소 조치.

### 4.2 서재 (모바일 우선)

**목록 항목 한 건**

| 위치 | 내용 |
|---|---|
| 제목 | 곡 제목 (수정 가능) |
| 부제 | 편곡자 · 마디 수 · 조/박자 · 악보 형태 · 인식 경로 |
| 오른쪽 위 | 마지막에 들은 파트 (localStorage). 없으면 표시 안 함 |
| 오른쪽 위(대체) | 확인할 곳 N군데 (경고가 남아 있을 때, 황토색) |
| 오른쪽 아래 | 진행 막대 (마지막 마디 / 전체 마디) |

**동작**

- 항목을 누르면 연습 화면으로 간다.
- 길게 누르면 이름 바꾸기 / 삭제 메뉴.
- 하단 고정 버튼: 새 악보 올리기.
- 빈 상태: "아직 올리신 악보가 없습니다. PC에서 첫 악보를 올려 보세요."

**정렬** — 최근 올린 순. 1차에는 검색·정렬 기능을 넣지 않는다.

### 4.3 악보 올리기 (데스크톱 전용, 1920)

**좌우 2단.** 왼쪽은 업로드와 진행 상태, 오른쪽은 품질 진단.

```
┌──────────────────────────┬──────────────────────────────────┐
│  파일 놓는 영역            │  입력 품질                        │
│  (끌어놓기 / 고르기)       │  ┌────┬────┬────┬────┐          │
│                          │  │해상도│오선 │기울기│보표 │          │
│  올린 파일 목록            │  └────┴────┴────┴────┘          │
│  - 진행 상태 표시          │                                  │
│  - 쪽 수 · 용량           │  판정 (판정 문구 + 조치 버튼)       │
│                          │                                  │
│                          │  쪽 미리보기 (썸네일 가로 배열)      │
└──────────────────────────┴──────────────────────────────────┘
```

**품질 지표 4종**

| 지표 | 값 | 판정 기준 |
|---|---|---|
| 추정 해상도 | DPI | 300 이상 양호 / 200~299 보통 / 199 이하 불량 |
| 오선 간격 | px | 10 이상 양호 / 8~9 경계 / 7 이하 불량 |
| 기울기 | 도 | 3 미만 양호 (자동 보정함) |
| 보표 검출 | 단 | 검출 성공 여부 |

**판정 문구** — 지표 조합에 따라 다르게 쓴다. 아래 문구를 그대로 쓴다.

| 조건 | 문구 |
|---|---|
| 오선 간격 10px 이상 | "품질이 좋습니다. 그대로 진행하시면 됩니다." |
| 오선 간격 8~9px | "인식은 되지만 가사 일부가 빠질 수 있습니다. 300DPI로 다시 스캔하시면 더 정확합니다." |
| 오선 간격 7px 이하 | "해상도가 조금 낮습니다. 오선 간격이 N픽셀입니다. 음표와 리듬은 대부분 읽히지만 가사 글씨가 뭉개져 일부만 인식됩니다. 300DPI로 다시 스캔하시면 훨씬 정확해집니다. 악보를 보며 부르실 거라면 이대로도 연습에는 지장이 없습니다." |
| 오선 미검출 | "악보를 찾지 못했습니다. 악보 전체가 나오도록 다시 찍어 주세요." |

**[다시 스캔하는 방법] 안내 내용**

1. 스캐너를 쓰신다면 해상도를 300DPI로 맞춰 주세요.
2. 휴대폰으로 찍으신다면 악보와 카메라를 평행하게 두고, 그림자가 지지 않게 해 주세요.
3. 한 장에 한 쪽씩 찍어 주세요.
4. 흑백보다 회색조가 낫습니다.

### 4.4 인식 확인 (데스크톱 전용, 1920)

**3분할 + 하단 띠.**

```
┌────┬───────────────────────────────────┬─────────────────┐
│ 쪽 │  원본 악보 + 인식 겹쳐보기           │  신뢰도          │
│ 목 │                                   │  ─────────      │
│ 록 │  [원본만] [겹쳐보기] [인식만]        │  경고 목록       │
│    │                                   │  · 항목별 교정   │
│ 1  │  (스크롤 · 확대/축소)               │                 │
│ 2  │                                   │                 │
│ …  │                                   │                 │
├────┴───────────────────────────────────┴─────────────────┤
│  파트별 음역 띠   S ▓▓▓▓  A ▓▓▓▓  T ▓▓▓▓  B ▓▓▓▓          │
└──────────────────────────────────────────────────────────┘
```

**겹쳐보기** — 원본 이미지 위에 인식한 음표를 반투명 표식으로 얹는다. 세 모드를 토글한다.

| 모드 | 표시 |
|---|---|
| 원본만 | 스캔/렌더 이미지 그대로 |
| 겹쳐보기 | 원본 + 인식 음표(파트별 색) 반투명 |
| 인식만 | 인식 결과만 다시 그림 |

파트별 색: 소프라노 `#7A2E3F`, 알토 `#9A6516`, 테너 `#3F6353`, 베이스 `#2C4A6E`.

**파트별 음역 띠 (하단)** — 이 화면의 핵심 진단 장치.

네 파트의 음 분포를 가로 띠로 그린다. 배경에 통상 음역을 옅게 깔고, 실제 분포를 진하게 얹는다. **옥타브 오류가 나면 띠가 통째로 위나 아래로 벗어나 한눈에 보인다.**

통상 음역 (MIDI):

| 파트 | 최소 | 최대 | 편안한 구간 |
|---|---|---|---|
| 소프라노 | 59 | 84 | 64~81 |
| 알토 | 53 | 77 | 57~74 |
| 테너 | 47 | 72 | 52~69 |
| 베이스 | 38 | 64 | 43~60 |

띠를 누르면 그 파트만 미리 듣는다.

**경고 목록** — 심각도 순으로 쌓는다. 각 항목은 코드·문구·마디 칩·조치 버튼으로 구성한다.

| 코드 | 심각도 | 문구 | 조치 |
|---|---|---|---|
| RANGE_VIOLATION | error | "{파트}가 보통 음역보다 {N}옥타브 {높/낮}습니다." | [한 옥타브 내리기/올리기] [그대로 두기] |
| VOICE_CROSSING | warn | "{A}가 {B}보다 낮게 읽혔습니다. 두 성부가 바뀌었을 수 있습니다." | [두 성부 맞바꾸기] |
| UNISON_AMBIGUOUS | warn | "음표가 하나뿐인 지점이 {N}곳입니다. {A}와 {B}가 같은 음을 부르는 것으로 처리했습니다." | 마디 칩 |
| DIVISI_SUSPECTED | warn | "음표가 3개 이상 겹친 지점이 {N}곳입니다. 가장 높은 음과 낮은 음만 사용했습니다." | 마디 칩 |
| MEASURE_DURATION_MISMATCH | warn | "{N}개 마디의 길이가 박자표와 맞지 않습니다." | 마디 칩 |
| VOICE_MISSING | error | "{파트}의 음표가 {N}개로 가장 많은 파트의 {M}%뿐입니다." | [파트 다시 나누기] |
| STAFF_COUNT_UNEXPECTED | info | "{N}단 중 아래 {M}단은 피아노 반주로 보고 제외했습니다." | [반주도 포함하기] |
| LYRICS_UNREADABLE | info | "가사를 읽지 못했습니다. 음표와 연주는 정상입니다." | — |
| UNKNOWN_GLYPH | info | "해석하지 못한 기호가 {N}종 있습니다." | — |
| TIME_SIGNATURE_GUESSED | warn | "박자표를 찾지 못해 {N}/{M}로 보았습니다. 다르면 아래에서 고쳐 주세요." | 박자표 선택 |

마디 칩을 누르면 가운데 악보 뷰가 그 마디로 이동하고 해당 마디를 강조한다.

**신뢰도** — 0~100 정수. 오선 5줄 게이지로 표현한다. 계산식은 `docs/OMR.md` 6장.

**교정 동작**

| 조치 | 효과 | 되돌리기 |
|---|---|---|
| 한 옥타브 내리기/올리기 | 해당 파트 전체 음을 ±12 이동 | 가능 |
| 두 성부 맞바꾸기 | 두 파트의 음표 배열을 교환 | 가능 |
| 박자표 고치기 | 박자표 변경 후 마디 길이 재검사 | 가능 |
| 반주도 포함하기 | 제외했던 보표를 파트로 편입 | 가능 |
| 그대로 두기 | 경고를 해결됨으로 표시 | 가능 |

교정은 낙관적으로 화면에 즉시 반영하고 서버에 저장한다. 실패하면 되돌리고 알린다.

### 4.5 연습 (모바일 우선)

├──────────────────────────────┤

**악보 뷰**

| 항목 | 규칙 |
|---|---|
| 표시 대상 | 원본 (스캔 이미지 또는 벡터 PDF 렌더) |
| 현재 마디 | 자주색 7% 사각형으로 강조 |
| 커서 | 현재 마디 왼쪽 경계에 세로선 |
| 자동 스크롤 | 시스템이 바뀔 때 해당 시스템을 화면에 들인다 (`scrollIntoView({block:'nearest'})`) |
| 끄기 | 상단 토글. 끄면 사용자 스크롤만 |
| 손 스크롤 감지 | 사용자가 직접 스크롤하면 자동 스크롤을 일시 정지하고, 3초 뒤 재개 |
| 마디 클릭 | 그 마디부터 재생 |

**자동 스크롤은 마디 좌표를 필요로 한다.** 인식 단계에서 `measureBoxes`를 반드시 산출해야 한다. 상세는 `docs/ARCHITECTURE.md` 4.3.

**파트 믹서**

| 요소 | 동작 |
|---|---|
| 파트 글자 + 오선 | 누르면 그 파트를 앞세운다 (음량 100, 나머지 40) |
| 오선 두께 | 앞세운 파트는 진하고 굵게, 나머지는 흐리게, 끈 파트는 점선 |
| 음량 숫자 | 0~100 정수 |
| 오른쪽 동그라미 | 소리 끄기/켜기 |

**끈 파트는 앞세울 수 없다.** 누르면 아무 일도 일어나지 않는다.

**듣는 방식**

| 방식 | 음량 |
|---|---|
| 고른 파트만 | 고른 파트 100, 나머지 0 |
| 고른 파트 크게 | 고른 파트 100, 나머지 40 |
| 다 같이 | 전부 80 |

**빠르기** — 40~120. 악보에 적힌 값을 기본으로 하고, 그 값을 안내 문구로 알린다.

**구간 반복** — 시작·끝 마디를 지정한다. 1차에는 악보 뷰에서 마디를 두 번 눌러 지정하는 방식으로 한다.

## 5. 오디오 규격

| 항목 | 값 |
|---|---|
| 음색 | 피아노 (단일 악기) |
| 재생 방식 | 브라우저. Tone.js Sampler + 압축 사운드폰트 |
| 사운드폰트 크기 | 2MB 이하 |
| 좌우 정위 | 소프라노 -0.5, 알토 -0.2, 테너 +0.2, 베이스 +0.5 |
| 음량 범위 | 0~100 → 게인 0~1 (지수 곡선) |
| 시작 지연 | 사용자가 재생을 누른 뒤 300ms 이내 |

**정위를 쓰는 이유** — 악기가 하나뿐이라 음량만으로는 파트가 섞인다. 합창단 배치대로 좌우로 벌리면 분리가 뚜렷해진다.

**첫 로딩** — 사운드폰트는 연습 화면에 들어갈 때 내려받는다. 서재에서 미리 받지 않는다. 내려받는 동안 재생 버튼에 진행 표시를 둔다.
