## 3. 지시서와 다르게 한 것 넷

**감리에서 중점적으로 보실 항목입니다.**

### 3.1 가사 — 간격 대신 음표 중점 (`a469e73`)

지시는 "진행폭이 아니라 **실제 간격**으로 판정하라"였습니다. **간격에는 신호가
없었습니다.**

```
음절 경계  Δx/폰트크기 = 0.59 · 0.68 · 0.72
음절 안쪽  Δx/폰트크기 = 0.61 · 0.61 · 0.68
```

완전히 겹칩니다. 조판이 음표를 촘촘히 놓으면 가사도 똑같이 촘촘해지므로
간격으로는 가를 수 없습니다.

**대신 음표 위치를 씁니다.** 가사 음절은 자기 음표에 정렬되므로, 이웃한 두
음표의 **중점**을 음절 경계로 삼았습니다. 처음에는 "글자보다 왼쪽의 가장
오른쪽 음표"에 붙였다가 한 칸씩 밀렸습니다(`Am·az·inggr`) — 음절은 음표머리
**중앙에** 놓이기 때문입니다.

남은 흠: 29곳 중 2곳이 단어 경계에서 한 글자 어긋납니다(`swee·tthe`, `aw·retch`).

### 3.2 폴리리듬 — 간격 대신 마디 길이 부풀림 (`68aea64` → `4335b2c`)

지시는 "화음 안에 서로 다른 음길이가 섞이면"이었습니다. **`closed_hard`에서 한
건도 잡히지 않았습니다.** 화음 안 음길이가 전부 균일했습니다.

계측으로 실제 증상을 찾았습니다. 두 성부의 리듬이 다르면 음표머리 X가 어긋나
**화음으로 묶이지 않고 순차 이벤트로 직렬화**됩니다.

```
m2 b0.00 d2 notes=[G5/79  E3/52]   27반음. 화음일 수 없다
m2 b0, 2, 4, 6                     4/4 마디인데 8박
```

처음에는 **간격**(인접 음 16반음 초과)을 신호로 썼습니다. **이것이 오탐을
냈습니다.** 테너와 베이스는 옥타브를 넘어 벌어지는 것이 정상이고 찬송가
편곡에서 10도·12도가 흔합니다. 감리 지적을 받아 **마디 총 길이 ≥ 박자표 ×
1.8**로 바꾸고 간격 신호를 완전히 제거했습니다. 간격은 직렬화의 결과일 뿐이니
원인을 봅니다.

감리가 제안한 보조 조건 둘은 **넣지 않았습니다.**

- "슬롯 수 초과" — `closed_hard` m2는 4/4에 슬롯 4개(각 `d2`)라 이 조건으로는
  안 걸립니다. 조건을 덜 걸어 잡히면 덜 겁니다.
- 보조 간격 신호 (3') — 마디 길이 신호만으로 잡히므로 불필요합니다.

### 3.3 `midi-gt.mts` — python + music21 대신 Node (`dcf7070`)

## 4. 예상과 달랐던 것

### 4.1 `closed_chord`의 `MEASURE_DURATION_MISMATCH`는 쉼표와 무관했다

`docs/tasks/P1.md` 3.3이 "쉼표 수정으로 사라지는지 확인하라"고 했고, 감리는
"쉼표 결함의 그림자로 보인다"고 추정했습니다. **둘 다 아니었습니다.**

이 픽스처는 마디 총 길이가 원래 전부 4.0입니다. 원인은 `parseScore`가
**박자표를 못 찾았을 때 경고 코드를 잘못 붙인 것**이었습니다. 문구는 "박자표를
찾지 못해 4/4로 가정했습니다"인데 코드는 마디 길이 불일치였습니다. 3.2에서
`TIME_SIGNATURE_GUESSED`로 바꾸자 사라졌습니다. **3.3이 아니라 3.2의 몫이었습니다.**

### 4.2 `open_satb`의 `treble_8`은 이미 인식되고 있었다

감리 3.2는 "파서가 `treble_8`을 인식하지 못하며 정확성이 `normalizeOctave`의
우연에 기대고 있다"고 진단했습니다. 근거는 글리프 목록에 `clefs.G_8`도 별도의
'8'도 없다는 것이었습니다.

**'8'은 글리프가 아니라 텍스트로 그려져 있습니다.**

```
테너 clefs.G@x75,y673  →  "8"@x78,y655   (오선 아래 2.7칸)
open_satb clefs = [treble, treble, treble8vb, bass, …]
```

`assignClefs`는 예전부터 그 텍스트를 검사하고 있었고 동작합니다. 없던 것은
인식이 아니라 **그 사실의 기록**이었습니다. 그래서 3.4의 실제 작업이
`octaveSource` 도입으로 바뀌었습니다.

진단 필드가 곧바로 값을 했습니다. 휴리스틱에 의존하는 곳은 `open_satb`가 아니라
**`closed_hard`와 `accidental`의 알토**였습니다.

### 4.3 `.d.ts` 16개 — 정확한 사실관계

`ae02f50`에서 `packages/omr-vector/src/`의 낡은 선언 파일 16개를 지웠습니다.
`types.d.ts`의 `WarningCode`에는 `TIME_SIGNATURE_GUESSED`도
`POLYRHYTHM_SUSPECTED`도 없었습니다. 정확히 "두 정의 공존"입니다.

**유입 시점** — 제가 커밋 메시지에 "P0에서 이식 소스와 함께 커밋했다"고 적었으나
**사실이 아닙니다.** 감리 지적으로 git을 추적했습니다.

| 커밋 | `.d.ts` |
| --- | --- |
| `8bf4719` P0 골격 | 0 |
| `3a8ab4b` P0 완료 | 0 |
| `ec97b90` 베이스라인 | 0 |

P0 트리에는 없었습니다. 따라서 "P0 감리가 `.ts`만 대조해 놓쳤다"도 사실이 아닙니다.

**근본 원인** — 감리는 "`outDir` 부재"라고 진단했으나 **이것도 사실이 아닙니다.**
모든 패키지에 `outDir`이 이미 있었습니다.

```
5c800b7 시점 packages/omr-vector/tsconfig.json
  "rootDir": "./src",
  "outDir": "./dist",
```

실제 원인은 `ec97b90`의 `scripts/baseline.mts`가 omr-vector 소스를 **상대경로로
직접 임포트**한 것입니다.

```
ec97b90 : import { parseScorePdf } from "../packages/omr-vector/src/parseScore.js";
현재    : import { parseScorePdf } from "@healing/omr-vector";
```

그 파일들이 `rootDir`이 `scripts`이고 `emitDeclarationOnly`인 프로젝트에 딸려
들어갔고, `rootDir` 밖이라 `outDir` 아래에 놓을 수 없어 tsc가 소스 옆에
떨궜습니다. 그때 본 TS6059가 그 증상이었습니다.

원인은 임포트를 패키지 경유로 바꾸며 이미 막혔고, `.gitignore` 규칙을 두 번째
방어선으로 뒀습니다(`b44c125`).

**기록으로 남기는 이유** — 감리자의 오진도 함께 적어야 다음에 같은 방식으로
원인을 갖다 붙이지 않습니다. 증상이 흔한 원인과 비슷하다고 단정하면 진짜 원인이
남습니다.

## 6. P2 인수인계

### 6.1 가장 중요한 계약 — `PAGE_RENDER_DPI`

**P2는 `@healing/schema`의 상수를 반드시 import해야 합니다.**

```ts
import { PAGE_RENDER_DPI, PDF_POINT_TO_PX } from "@healing/schema";
// PAGE_RENDER_DPI = 300
// PDF_POINT_TO_PX = 300 / 72 = 4.1667
```

P1이 `measureBoxes` 좌표를 이 배율로 산출했습니다. **P2가 페이지 이미지를 다른
해상도로 렌더하면 마디 좌표가 통째로 어긋나 자동 스크롤이 무너집니다.** 값을
따로 적지 말고 이 상수를 쓰십시오. 두 곳에 적으면 언젠가 갈라집니다.

증상이 조용합니다 — 이미지도 나오고 좌표도 나오는데 강조 사각형만 음표와 다른
자리에 그려집니다. 그래서 계약으로 못박습니다.

### 6.2 그 밖에 넘기는 것

| 항목 | 내용 |
| --- | --- |
| `ParseResult` | `@healing/schema`가 정본. `omr-vector`는 재수출만 함 |
| `measureBoxes` 좌표계 | 페이지 이미지 좌표계(px, Y 아래로 증가). 뒤집기는 `buildMeasureBoxes` 안에서만 일어남 |
| 상자 범위 | 시스템 전체(맨 위 오선 윗줄 ~ 맨 아래 오선 아랫줄). 파트 하나가 아님 |
| `measureBoxes` 빈 배열 | 산출 실패 시의 규격. 자동 스크롤은 경과 시간 비례로 대체 |
| `octaveSource` | 진단용. **사용자에게 보이지 않습니다** |
| `tempoBpm` | 못 찾으면 `null`. 화면이 기본값을 씁니다. 추정하지 않았습니다 |
| 측정 도구 | `pnpm baseline` — 픽스처 11개의 수치를 표로 냅니다. 회귀 확인에 쓰십시오 |
| LilyPond | `c:\dev\chorus\lilypond\bin\lilypond.exe` (2.26.0). 저장소 바깥이며 지우면 픽스처를 재생성할 수 없습니다. `docs/OMR.md` 7장 |

### 6.3 P2가 처음 만날 것

`song_pages` 이미지를 만들 때 pdfjs로 300DPI 렌더를 하게 됩니다. `omr-vector`가
이미 `pdfjs-dist@4.10.38`을 쓰므로 같은 버전을 쓰십시오. **캐럿을 붙이지
마십시오** — 5.x에서 `doc.destroy()`가 사라지고 선 연산자 노출이 달라집니다.
