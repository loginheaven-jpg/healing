## 2. 감리자의 오진 세 건

**이 절이 이번 감리에서 가장 중요하다.** 내가 세 번 틀렸고, 두 건은 작업자가 잡았다.

### 2.1 `open_satb` 테너 음역 (내가 스스로 잡음)

`docs/TASKS.md` P1 완료 기준에 "테너 53~65, `VOICE_CROSSING` 없음"이라 적었다. **틀렸다.** LilyPond MIDI를 직접 뽑아 65~77이 정답임을 확인했다. `\clef "treble_8"`은 적은 음이 곧 울리는 음이고 그리는 위치만 올린다. 반대로 봤다.

**그대로 뒀으면 정상 동작을 망가뜨렸을 기준이다.**

### 2.2 `treble_8` 미인식 (작업자가 잡음)

`P0-REVIEW.md` 3.2에 "파서는 `treble_8`을 인식하지 못한다. 결과가 맞는 이유는 `normalizeOctave`의 우연"이라 적었다. **틀렸다.**

v0 원본 `staffDetect.ts`를 확인했다.

```
84: `treble8vb`(테너용 옥타브 이동 음자리표)는 글리프 이름으로 구분되지 않는
85:  경우가 있어, 음자리표 아래의 작은 "8" 텍스트로도 판정한다.
131:      t.text === "8" &&
136:      if (has8) clef = "treble8vb";
```

**이식 전부터 동작하고 있었다.**

내 실수의 원인은 명확하다. **글리프 목록만 보고 텍스트 배열을 확인하지 않았다.** `clefs.G`에 옥타브 표시가 없다는 것만으로 "인식 못 한다"고 단정했다. `staffDetect.ts`를 열어봤으면 30초에 끝났을 확인이다.

다만 **밑에 깔린 우려는 실재했다.** `octaveSource`를 도입하자 `closed_hard`와 `accidental`의 알토가 `range-heuristic`에 의존한다는 것이 드러났다. 진단 필드가 곧바로 값을 했다. 결과적으로 3.4의 작업이 "인식 구현"에서 "근거 기록"으로 바뀐 것은 옳다.

### 2.3 `.d.ts` 근본 원인 = `outDir` 부재 (작업자가 잡음)

"`outDir`이 없어 tsc가 소스 옆에 떨궜다"고 단정했다. **틀렸다.** `5c800b7` 시점 `tsconfig.json`에 `outDir: "./dist"`가 이미 있었다.

실제 원인은 `scripts/baseline.mts`가 소스를 상대경로로 직접 임포트해 `rootDir` 밖 파일이 딸려 들어간 것이다. 임포트를 패키지 경유로 바꾼 것이 근본 대응이고, `.gitignore`는 두 번째 방어선이다.

**증상이 흔한 원인과 비슷하다고 단정한 것이 실수다.** 유입 시점(2.3의 P0 대 P1)은 git으로 확인했으면서 원인은 확인하지 않았다.

### 2.4 교훈

세 건 모두 같은 실패 유형이다. **코드를 열어보지 않고 관측 하나로 단정했다.**

| 오진 | 확인했어야 할 것 | 걸리는 시간 |
|---|---|---|
| 테너 음역 | LilyPond MIDI | 2분 |
| `treble_8` | `staffDetect.ts` |30초 |
| `outDir` | 해당 시점 `tsconfig.json` | 30초 |

앞으로 감리에서 "파서가 X를 못 한다"고 쓰기 전에 **해당 코드를 먼저 연다.**

## 3. 특히 잘한 것

**지시를 그대로 따르지 않고 계측으로 검증한 것.** 3.5 가사와 3.6 폴리리듬 모두 내 지시대로 하면 안 되는 이유를 수치로 제시했다. 특히 가사의 간격 분포(경계 0.59·0.68·0.72 대 안쪽 0.61·0.61·0.68)는 **신호가 애초에 없다**는 것을 보여준다. 시키는 대로 만들었으면 동작하지 않는 코드가 남았을 것이다.

**조건을 덜 걸어 잡히면 덜 건 것.** 폴리리듬에서 내가 제안한 "슬롯 수 초과"와 보조 간격 신호를 둘 다 뺐다. 불필요한 조건은 나중에 다른 악보에서 미검출을 만든다.

**픽스처 하나에 한 가지만 시험한다는 원칙.** `tenor_octave`와 `wide_tb` 두 번 모두 덧줄 흡수를 만나 픽스처 쪽을 고쳤다. 파서를 고쳤으면 시험 대상이 흐려졌을 것이다. 그리고 **흡수 현상 자체는 한계 표에 기록**했다.

**`4.1`의 발견.** `closed_chord`의 `MEASURE_DURATION_MISMATCH`가 쉼표와 무관했고, 실은 박자표 미검출 시 경고 코드를 잘못 붙인 것이었다는 지적이 정확하다. 나와 지시서가 함께 추정을 틀렸고 작업자가 원인을 찾았다.

**감리자의 오진을 기록한 것.** "증상이 흔한 원인과 비슷하다고 단정하면 진짜 원인이 남습니다"는 문장은 이 프로젝트가 계속 지켜야 할 태도다.
