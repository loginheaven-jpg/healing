# P2 작업지시서 — 저장 · 업로드 · 인증

> `docs/TASKS.md` P2를 **이 문서로 대체한다.** P1 산출물과의 계약이 반영돼 있다.

- **선행 조건**: P1 합격. 시험 38건 · 린트 오류 0 · 경고 0 상태에서 시작한다.
- **원칙**: **38건은 끝까지 통과해야 한다.** P2는 파서를 건드리지 않는다.

## 0. P1에서 넘어온 계약

### 0.1 반드시 지킬 것 — 렌더 배율

```ts
import { PAGE_RENDER_DPI, PDF_POINT_TO_PX } from "@healing/schema";
```

**페이지 이미지를 이 해상도로 렌더한다.** P1이 `measureBoxes`를 이 배율로 산출했다. 다른 값으로 렌더하면 마디 좌표가 통째로 어긋난다.

**증상이 조용하다.** 이미지도 나오고 좌표도 나오는데 강조 사각형만 음표와 다른 자리에 그려진다. P4에 가서야 드러나고, 그때는 원인이 P2인지 P4인지 가리기 어렵다.

**숫자를 코드에 적지 마라.** `300`이나 `4.1667`이 소스에 나타나면 잘못이다.

### 0.2 좌표계

`measureBoxes`는 **페이지 이미지 좌표계(px, Y 아래로 증가)**다. 이미 뒤집혀 있다. **P2에서 다시 뒤집지 마라.**

`song_pages.width/height`는 실제 렌더된 이미지의 픽셀 크기다. 클라이언트가 표시 크기와의 비율을 계산하는 근거이므로 정확해야 한다.

### 0.3 그 밖

| 항목 | 내용 |
|---|---|
| `ParseResult` | `@healing/schema`가 정본 |
| `measureBoxes` 빈 배열 | 산출 실패 시의 규격. 오류가 아니다 |
| `octaveSource` | 진단용. **사용자에게 보이지 않는다.** DB에 저장하지 마라 |
| `tempoBpm` | `null` 가능. 화면이 기본값을 쓴다 |
| `pdfjs-dist` | **정확히 `4.10.38`.** 캐럿 금지 |

## 2. 세부 지시

### 2.1 DB 스키마

`docs/ARCHITECTURE.md` 4.2절 SQL을 그대로 쓴다. Drizzle로 옮기고 마이그레이션을 생성·적용한다.

**하지 말 것**

- **`users` 테이블을 만들지 마라.** 1차에 회원 개념이 없다.
- **"나중을 위해" nullable 컬럼을 미리 만들지 마라.** 쓰지 않는 컬럼은 혼란만 부른다.
- `octaveSource`를 저장하지 마라. 진단용이다.

**주의** — `song_measures`는 `measureBoxes`를 그대로 담는다. `(song_id, measure)`가 기본키다. 한 마디가 두 쪽에 걸치는 경우는 1차에 없다고 본다.

**완료 기준** — 마이그레이션이 빈 DB에 적용되고, 롤백 후 재적용도 된다.

### 2.2 R2 클라이언트

`@aws-sdk/client-s3`로 R2에 접근한다. 필요한 것은 넷이다.

| 기능 | 용도 |
|---|---|
| 서명 PUT URL 발급 | 브라우저가 직접 업로드 |
| 객체 읽기 | 워커·서버가 원본을 읽음 |
| 서명 GET URL 발급 (1시간) | 클라이언트가 페이지 이미지를 봄 |
| 객체 삭제 | 곡 삭제 시 |

`scripts/r2-smoke.ts`가 P0에서 이미 이 흐름을 검증했다. 그 코드를 참고하되 **서비스 코드로 옮겨 재사용 가능한 모듈로 만들어라.**

**R2 CORS 정책 등록이 필요하다.** 브라우저가 R2로 직접 PUT하므로 오리진을 허용해야 한다. `docs/DEPLOY.md`에 절차를 추가하라.

### 2.3 통행 암호 인증

| 항목 | 값 |
|---|---|
| 암호 | 환경변수 `ACCESS_PASSKEY`. **코드에 박지 마라** |
| 쿠키 | `HttpOnly`, `Secure`, `SameSite=Lax`, 30일 |
| 방식 | HMAC 서명 토큰. **세션 저장소를 두지 마라** |
| 실패 제한 | 같은 IP 3회 실패 시 10초 대기 |

**모든 `song.*` 프로시저가 이 쿠키를 요구한다.** 하나라도 빠지면 안 된다.

`// TODO(v2): 접근 통제 재설계` 주석을 인증 모듈에 남겨라. 통행 암호 하나로는 링크 유출을 막지 못한다는 사실이 기록으로 남아야 한다.

**완료 기준** — 쿠키 없이 `song.list`를 부르면 401. 틀린 암호 3회 뒤 4회째가 10초 지연.

### 2.4 파일 머리글 판별

**확장자를 믿지 마라.** 실제로 `.pdf`인데 ZIP인 파일을 겪었다(`docs/TESTLOG.md` 1장).

| 머리글 | 판정 |
|---|---|
| `%PDF` | PDF |
| `PK` | ZIP (이미지 묶음) |
| 그 외 | 단일 이미지 |

PDF는 다시 벡터 여부를 가른다. `parseScorePdf`가 이미 판정하고 `VectorParseUnavailable`을 던진다. **그 예외를 잡아 이미지 경로로 넘겨라.** 판정 로직을 새로 짜지 마라.

### 2.5 페이지 이미지 렌더 — 계약 지점

pdfjs로 PDF를 **`PAGE_RENDER_DPI`** 해상도로 렌더해 PNG로 만들고 R2에 올린다.

```
배율 = PDF_POINT_TO_PX      // 300/72
캔버스 크기 = 페이지 포인트 크기 × 배율
```

**검증을 반드시 넣어라.** 렌더한 이미지 크기와 `measureBoxes` 좌표가 맞는지 확인하는 시험이다.

```
모든 box에 대해:
  box.x + box.w <= song_pages.width
  box.y + box.h <= song_pages.height
```

이 시험이 P2의 가장 중요한 안전장치다. **계약이 깨지면 여기서 잡힌다.**

Node에서 pdfjs 렌더링은 canvas가 필요하다. `@napi-rs/canvas`를 권한다. 순수 JS 대안이 있으면 제안하라.

**완료 기준** — `open_satb.pdf`를 넣으면 쪽 수만큼 PNG가 생기고, 위 부등식이 9개 마디 전부에서 성립한다.

### 2.6 벡터 경로 ingest

```
ingest({ fileKey, fileName })
  → R2에서 원본 읽기
  → 머리글 판별
  → 벡터면 parseScorePdf 즉시 실행
  → songs / song_pages / song_parts / song_measures / song_lyrics / song_warnings 저장
  → { songId, immediate: true } 반환
```

**한 트랜잭션으로 묶어라.** 중간에 실패하면 반쯤 저장된 곡이 남는다.

이미지면 `songs.status = pending`으로 만들고 pg-boss에 작업을 넣은 뒤 `{ songId, immediate: false, jobId }`를 돌려준다. **워커는 P3에서 만든다.** P2에서는 큐에 넣히는 것까지만 한다.

### 2.7 tRPC 라우터

`docs/ARCHITECTURE.md` 5.2절 표대로 만든다.

**`song.get`이 돌려주는 것**

```ts
{
  ...ParseResult,
  id, title, composer, arranger, status,
  pages: { pageNo, url, width, height }[],   // url은 서명 GET (1시간)
}
```

서명 URL은 **곡 상세를 요청할 때 발급한다.** DB에 저장하지 마라. 만료된다.

### 2.8 교정 API

```ts
type Edit =
  | { kind: "octaveShift"; part: Part; semitones: 12 | -12 | 24 | -24 }
  | { kind: "voiceSwap"; a: Part; b: Part }
  | { kind: "timeSignature"; numerator: number; denominator: number }
  | { kind: "includeStaff"; staffIndex: number; part: Part }
  | { kind: "resolveWarning"; warningId: number };
```

| 규칙 | 내용 |
|---|---|
| 이력 | `song_edits`에 남긴다 |
| 되돌리기 | 마지막 하나를 취소한다. 1차에는 한 단계면 충분 |
| 재계산 | `timeSignature` 변경 시 마디 길이를 다시 검사하고 `MEASURE_DURATION_MISMATCH`를 갱신한다 |
| 신뢰도 | 교정 후 다시 계산한다. `resolved` 경고는 감점에서 빠진다 |

**`octaveShift`는 `song_parts.notes`의 `p`만 바꾼다.** `measureBoxes`는 건드리지 않는다. 음높이가 바뀌어도 마디 위치는 그대로다.

**`includeStaff`는 1차에서 가장 어렵다.** 제외했던 보표를 파트로 편입하려면 다시 파싱해야 한다. **원본을 다시 읽어 `useStaves`를 달리 주는 방식으로 하라.** 부분 수정하지 마라.

## 3. 완료 기준

| # | 기준 |
|---|---|
| 1 | 벡터 PDF를 올리면 1초 안에 `status = ready`가 되고 `song.get`이 완전한 `ParseResult`를 돌려준다 |
| 2 | `song_pages`에 쪽 수만큼 행이 생기고 서명 URL로 이미지가 열린다 |
| 3 | `song_measures`에 마디 수만큼 행이 생긴다 |
| 4 | **모든 마디 상자가 페이지 이미지 크기 안에 들어온다** (2.5의 부등식) |
| 5 | 렌더 배율이 `@healing/schema` 상수에서 온다. 소스에 `300`이나 `4.16`이 없다 |
| 6 | 쿠키 없이 `song.list` 호출 시 401 |
| 7 | 틀린 암호 3회 뒤 4회째가 10초 지연 |
| 8 | 확장자가 `.pdf`인 ZIP 파일이 이미지 경로로 분기한다 |
| 9 | 이미지 파일을 올리면 `status = pending`이 되고 작업이 큐에 들어간다 |
| 10 | 교정 후 신뢰도가 다시 계산되고 되돌리기가 동작한다 |
| 11 | ingest 중간 실패 시 반쯤 저장된 곡이 남지 않는다 |
| 12 | **`pnpm test` 38건 + 새로 추가한 시험 전부 통과**, 린트 오류 0 경고 0 |

**4번과 5번이 P2의 핵심이다.** 나머지가 다 되어도 이 둘이 깨지면 P4에서 자동 스크롤이 무너진다.
