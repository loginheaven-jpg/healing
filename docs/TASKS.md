# TASKS — 작업지시서

## 읽는 법

각 단계는 **완료 기준**을 만족해야 다음으로 넘어갑니다. 기준은 실행해서 확인할 수 있게 썼습니다. "구현했다"가 아니라 "돌려서 이 결과가 나온다"가 완료입니다.

**단계를 건너뛰지 마십시오.** 특히 P1의 회귀 테스트를 통과하지 않은 채 P2로 가면, 나중에 인식이 틀린 원인이 파서인지 저장인지 화면인지 가릴 수 없게 됩니다.

각 단계를 마치면 **무엇을 했고 무엇이 남았는지 보고**하십시오. 판단이 필요한 지점에서는 진행하지 말고 물어보십시오.

## P0. 저장소 골격

### 할 일

1. 모노레포 골격을 만든다. pnpm workspace.

```
healing-choir/
├── apps/web/{client,server}
├── apps/omr-worker
├── packages/{omr-vector,schema,db}
├── docs/          (이미 있음)
└── ui/            (이미 있음, 빌드 대상 아님)
```

2. `packages/omr-vector/`에 이식된 소스가 이미 있다. 그대로 두고 빌드만 통하게 한다.
3. TypeScript, ESLint, Prettier, Vitest 설정.
4. `.env.example` 작성. `docs/ARCHITECTURE.md` 7.3절 목록대로.
5. Railway 3개 서비스와 Postgres, Cloudflare R2 버킷을 만든다. 빈 앱이라도 배포가 통하는지 확인한다.

### 주의

- `pdfjs-dist`는 **정확히 `4.10.38`**로 고정한다. `^`를 쓰지 않는다. 이유는 `docs/OMR.md` 5.7.
- `ui/` 폴더는 시안이다. 빌드에 포함하지 않는다.

### 완료 기준

- `pnpm build`가 통과한다.
- `pnpm test`가 실행된다 (테스트가 0건이어도 됨).
- Railway에서 web 서비스가 `/health`에 200을 돌려준다.
- R2 버킷에 파일을 올리고 서명 URL로 읽어 오는 스크립트가 동작한다.

## P1. 벡터 파서 수정과 회귀 테스트

**이 단계가 가장 중요합니다.** 화면을 만들기 전에 인식이 옳아야 합니다.

### 할 일

`docs/OMR.md` 5장의 결함 7건을 순서대로 고칩니다.

| 순서 | 결함 | 문서 절 | 난이도 |
|---|---|---|---|
| 1 | 쉼표 누락 → 박 위치 붕괴 | 5.1 | 낮음 |
| 2 | 박자표 미인식 | 5.2 | 낮음 |
| 3 | 옥타브 이조 음자리표 | 5.3 | 중간 |
| 4 | 성부마다 다른 리듬 (검출만) | 5.4 | 낮음 |
| 5 | 붙임줄 (검출만) | 5.5 | 낮음 |
| 6 | 가사 병합 임계값 | 5.6 | 중간 |
| 7 | pdfjs 버전 고정 | 5.7 | 완료됨 |

동시에 `ParseResult`를 `docs/ARCHITECTURE.md` 4.1절 정의로 확장합니다.

| 추가 필드 | 설명 |
|---|---|
| `rests` | 파트별 쉼표. 결함 1의 산물 |
| `measureBoxes` | 마디 좌표. 자동 스크롤에 필수 |
| `tempoBpm` | 악보에 적힌 빠르기 |

**`measureBoxes` 산출** — `staffDetect`와 `systemGroup`이 이미 오선·시스템·마디선 좌표를 압니다. PDF 좌표계를 렌더 이미지 좌표계로 변환하십시오. 렌더 배율을 곱하고 Y축을 뒤집으면 됩니다.

### 하지 말 것

- `pdfExtract.ts`의 CTM 추적을 리팩터링하지 마십시오. `docs/OMR.md` 4.1.
- `noteParse.ts`의 기둥/마디선 두께 판별을 바꾸지 마십시오. `docs/OMR.md` 4.2.
- `voiceSplit.ts`의 넓은 음역 정책을 좁히지 마십시오. 이유가 주석에 있습니다. 대신 5.3의 지시대로 음자리표를 제대로 읽으십시오.

### 완료 기준

`packages/omr-vector/fixtures/`의 모든 픽스처가 아래를 만족합니다.

| 픽스처 | 기준 |
|---|---|
| `rest_test.pdf` | 박자 **3/4**, 첫 8분음표 `b1.00`, 마디 길이 3.0, 마디 길이 경고 없음 |
| `closed_chord.pdf` | 4파트 각 33음표, 음역 분리 (72~81 / 64~72 / 55~64 / 48~57), 신뢰도 90 이상 |
| `closed_stems.pdf` | `closed_chord`와 같은 결과 |
| `open_satb.pdf` | 테너 음역 **53~65**, `VOICE_CROSSING` 경고 없음, 가사 `A-ma-zing` 형태 |
| `three_staff.pdf` | 반주 보표 제외, 4파트 각 7음표, 신뢰도 90 이상 |
| `single_staff.pdf` | `layout: "single"`, 파트 균형 경고 없음 |
| `accidental.pdf` | 조표를 임시표로 오인하지 않음 |
| `closed_hard.pdf` | `POLYRHYTHM_SUSPECTED` 경고 발생 |

모든 픽스처에서 `measureBoxes`가 마디 수만큼 나옵니다.

**보고 사항** — 각 픽스처의 수정 전/후 수치를 표로 제출하십시오.

## P2. 저장과 업로드

### 할 일

1. `packages/db`에 Drizzle 스키마 작성. `docs/ARCHITECTURE.md` 4.2절 SQL 그대로.
2. 마이그레이션 생성·적용.
3. R2 클라이언트 (`@aws-sdk/client-s3`). 업로드 서명 URL 발급, 객체 읽기, 서명 다운로드 URL 발급.
4. tRPC 라우터: `auth.*`, `song.list/get/createUploadUrl/ingest/status/rename/delete`.
5. 통행 암호 인증. HMAC 서명 쿠키. `docs/ARCHITECTURE.md` 5.1.
6. 파일 머리글 판별 (PDF / ZIP / 이미지).
7. 벡터 경로: `ingest` 안에서 즉시 파싱하고 DB에 저장.
8. 페이지 이미지 생성: 벡터 PDF는 pdfjs로 300DPI 렌더 → PNG → R2.

### 주의

- **`users` 테이블을 만들지 마십시오.** 1차에 회원 개념이 없습니다. 나중에 쓸 거라고 미리 nullable 컬럼을 만들지도 마십시오.
- 통행 암호는 환경변수 `ACCESS_PASSKEY`로 둡니다. 코드에 박지 마십시오.
- 3회 실패 시 10초 대기를 겁니다.

### 완료 기준

- 벡터 PDF를 올리면 1초 안에 `songs.status = ready`가 되고 `song.get`이 완전한 `ParseResult`를 돌려준다.
- `song_pages`에 쪽 수만큼 행이 생기고, 서명 URL로 이미지가 열린다.
- `song_measures`에 마디 수만큼 행이 생긴다.
- 통행 암호 없이 `song.list`를 호출하면 401.
- 틀린 암호 3회 뒤 4회째는 10초 대기 후 응답.

## P3. 이미지 인식 워커

### 할 일

1. `apps/omr-worker` Dockerfile. `docs/ARCHITECTURE.md` 3.5절 그대로.
2. pg-boss 소비자. `songs.status = pending`인 작업을 가져온다.
3. 전처리 파이프라인. `docs/ARCHITECTURE.md` 3.1절 규격.
4. 품질 진단. 3.2절 기준. 결과를 `songs`에 기록.
5. Audiveris CLI 호출. 3.3절 규격.
6. MusicXML → `ParseResult` 변환. `docs/OMR.md` 8장.
7. 페이지 이미지를 R2에 올린다 (전처리된 PNG).
8. `measureBoxes` 산출. 수평·수직 투영으로 오선과 마디선을 찾는다.

### 주의 (실패하기 쉬운 지점)

1. **Tesseract 언어 데이터.** `apt install tesseract-ocr-kor`은 쓸 수 없습니다. 레거시 포함 버전을 내려받아야 합니다. `docs/ARCHITECTURE.md` 3.4. 파일 크기로 확인하십시오. kor은 약 15MB여야 합니다.
2. **deb 설치가 실패합니다.** 후처리 스크립트가 종료 코드 3으로 죽지만 본체는 정상 설치됩니다. `dpkg -i ... || true`로 넘기십시오.
3. **`<voice>` 태그를 믿지 마십시오.** Audiveris가 자주 틀립니다. 음높이 정렬로 성부를 나누십시오.
4. **파트 이름을 믿지 마십시오.** `Voice`, `P3-Staff1` 같은 이름이 나옵니다.
5. **메모리 4GB.** 실측에서 1.4GB를 썼습니다. 여유가 필요합니다.

### 완료 기준

- `reference_satb_300dpi.png`를 넣으면 4보표 4마디, 조표 -3, 박자 3/4, 음표 40개가 나온다.
- `evaluate_omr.py`로 채점해 음정·리듬 정확도 90% 이상.
- `reference_satb_112dpi.png`를 넣으면 품질 진단에서 거부되고 `songs.status = failed`, `error_message`에 존대체 안내가 남는다.
- 실제 스캔본(`score1.jpg` 상당)에서 4보표 12마디가 나온다.
- 쪽당 처리 시간 180초 이내.

## P4. 연습 화면 (모바일)

### 할 일

1. `ui/mobile.html` 시안대로 서재와 연습 화면 구현.
2. 악보 뷰: `song_pages` 이미지를 세로로 이어 붙이고, `song_measures` 좌표로 현재 마디를 강조.
3. 자동 스크롤: 시스템이 바뀌면 `scrollIntoView({ block: 'nearest' })`. 토글로 끌 수 있음.
4. 손 스크롤 감지: 사용자가 직접 스크롤하면 자동 스크롤 3초 정지 후 재개.
5. `MidiPartPlayer` 구현. `docs/ARCHITECTURE.md` 6장.
6. 파트 믹서, 듣는 방식 3종, 빠르기, 구간 반복.
7. 연습 설정을 localStorage에 저장·복원.

### 주의

- **시안의 CSS 변수를 그대로 쓰십시오.** 색과 글꼴을 임의로 바꾸지 마십시오.
- **끈 파트는 앞세울 수 없습니다.** 눌러도 아무 일이 없어야 합니다.
- 사운드폰트는 연습 화면 진입 시 내려받습니다. 서재에서 미리 받지 마십시오.
- `prefers-reduced-motion`이면 자동 스크롤을 즉시 이동으로 바꿉니다.

### 완료 기준

- 재생하면 커서가 마디를 따라 움직이고 악보가 따라 내려간다.
- 파트를 바꾸면 즉시 음량이 바뀐다. 다시 로딩하지 않는다.
- 빠르기를 바꿔도 재생이 끊기지 않는다.
- 마디를 누르면 그 마디부터 재생된다.
- 곡을 나갔다 들어오면 마지막 파트·마디·빠르기가 복원된다.
- 375px 폭에서 가로 스크롤이 생기지 않는다.
- 재생 시작 지연이 300ms 이내.

## P5. 올리기와 인식 확인 화면 (데스크톱)

### 할 일

1. `ui/desktop.html` 시안대로 구현. 1920×1080 기준.
2. 올리기: 끌어놓기, 진행 상태, 품질 진단 4지표, 판정 문구.
3. 인식 확인: 3분할 + 하단 음역 띠.
4. 겹쳐보기 3모드 (원본만 / 겹쳐보기 / 인식만).
5. 파트별 음역 띠. 통상 음역을 배경에 깔고 실제 분포를 얹는다.
6. 경고 목록과 교정 동작. `song.applyEdit` / `song.undoEdit`.
7. 마디 칩을 누르면 악보 뷰가 그 마디로 이동.
8. 휴대폰으로 접근하면 "PC에서 이용해 주세요" 안내.

### 주의

- 판정 문구는 `docs/SPEC.md` 4.3절의 문장을 **그대로** 쓰십시오. 임의로 바꾸지 마십시오.
- 경고 문구도 4.4절 표의 형식을 지키십시오.
- 교정은 낙관적으로 반영하고, 실패하면 되돌리고 알립니다.

### 완료 기준

- 저해상도 스캔을 올리면 오선 간격 수치와 함께 판정 문구가 뜬다.
- 테너 옥타브 오류가 있는 곡에서 음역 띠가 위로 벗어나 보이고, [한 옥타브 내리기]를 누르면 즉시 제자리로 온다.
- 되돌리기가 동작한다.
- 마디 칩을 누르면 악보가 그 마디로 이동한다.
- 겹쳐보기에서 인식 음표가 원본 음표와 겹쳐 보인다.
